# D1 FFN 驻留融合审查（主 agent 复核）

Gemini 提供了两种独立原型：A 将完整 512-word 激活保存在 RF；B 按 64-word 激活片段生成，并立即累加 W2 输出。原始 worker 报告、命令、失败尝试及固定环境复跑结果保存在 `project/campaigns/gemini-fusion-review/`。

## 可采纳的结果

- 孤立合成 FFN 的功能测试在 A/B 两个方案上通过，报告最大绝对误差 2.136230e-04。
- 原型基线/A/B timing 为 28,970 / 28,646 / 28,639 cycles，局部收益约 1.1%。HBM 写从 5,120 降到 512 bytes，减少 4,608 bytes；读从 532,480 降到 527,872 bytes。
- 可以保留跨 W1/GELU/W2 的值生命周期和 RF 分区设计，作为以后多 SM 方案的局部融合组件。单独这一变换的已测收益有限，优先级低于多 SM 接入。

## 必须修正的 worker 结论

- 原报告的“所有硬件配置都可用”容量证明遗漏了 B 权重 tile：16×64=1024 words。当前代码只在 vector_lanes 为 8/16 时满足单分区容量；32/64 时必须调整 tile。活跃中间值只有 64/128 words 不构成完整容量证明。
- 5120→512 bytes 是减少 4.5 KiB，原报告的 11.25 KiB 写入节省不成立。
- 静态 FOR 会在执行前展开，不能把循环计数器当作运行时流水间隔。
- 原报告里的 assembly 带有占位符和伪表达式，不可直接当作合法 ISA 使用；保存的 Python 原型才是可复跑证据。
- “zero regressions”没有完整 P1+D1 grade 支持。当前只通过了孤立随机输入检查，不能提升为提交候选。

下一步如需接入，必须增加 recipe 开关、按硬件检查所有 operand 分区容量、使用 Builder 的事件命名，并完整验证两例。原始报告中的无条件替换建议不直接采用。
