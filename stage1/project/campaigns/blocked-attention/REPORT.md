## Implementation and execution plan

`project/compiler.py:Builder.attention_blocked` handles P1's 64-token prompt only. For each layer/batch: LN1 → QKV → export K/V in 32-token panels → Attention in 16-query blocks, streaming 32-key/value panels → WO/residual/LN2 → W1/GELU/W2/residual. All stages in cand-106 execute on SM0, one persistent WG. First generated token and D1 use the prior paths.

RF4 holds a 16×64 score/probability tile; RF0 queries, RF1 streamed K/V, RF2 context, RF3 scalar reductions. Strided RF matrix views eliminate packing. Softmax retains per-row causal-prefix reduction and explicitly zeros future columns. This computes extra masked QK/PV work but batches small operations and reuses KV across queries. Public K/V exports remain exactly once per element.

## Next structural decision

Further isolated Attention optimization has at most 1.087× P1 upside even if its remaining cost vanishes. Stop tuning its tiles. W1+GELU+W2 now occupy 61.05%: accelerating that whole region by 2.203× would reach 1.5× P1; 3.28× would yield about 1.737×. These are Amdahl targets, not achieved speedups. A row-block persistent MLP that reduces W1→GELU→W2 materialization and event count is the strongest next P1 hypothesis; it must be evaluated as a distinct outer structure, with validation preflight before any multi-WG grade. It cannot be claimed to fit memory in advance.

Do not launch the remaining W2/QKV combinations with this same event representation, and do not bypass the cost gate. D1 persistent execution remains secondary: its weights are already largely cached, so target repeated NoC/RF transfers rather than assuming eight physical HBM reloads. The original multi-SM success criteria remain open.
