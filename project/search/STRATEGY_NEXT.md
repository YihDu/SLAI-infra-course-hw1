# 面向万分级目标的搜索策略

目标仍是冻结 evaluator 的 eligible score；万分级是搜索目标，不是已验证可达上界。当前完整验证的起点是 cand-095：P1=8,522,411、D1=718,132，score=2567.954。到 10,000 分需要将当前周期乘积再降约 15.16 倍；到 30,000 分约 136.48 倍。若两个案例相对原始 baseline 的加速比相等，10,000 分对应约 P1=3,099,700、D1=130,203，30,000 分对应约 P1=1,033,233、D1=43,401。允许采用不对称的加速组合。

## 目标与资源分配

接受任何正确、eligible 且综合分数更高的候选，即使一个案例相对 incumbent 退化。保留 P1/D1 Pareto、面积以及结构分支，允许先释放面积再升级执行资源。`records.py` 已移除“双案例都不得退化”的附加提升条件。

下一阶段将开发与实验预算按 60% 结构原型、25% 联合硬件、15% 参数细调分配。这是主 agent 的研究调度；现有数值 proposer 不会凭空生成尚未实现的编译器变换。数值搜索器承担已实现结构的内部参数优化，新结构必须先增加可验证的生成器实现。

## 外层空间：并行分工 × 数据驻留 × 融合边界 × 流水方式

1. P1 从 batch、GEMM N 列和 attention head 三种切分建立多 SM 原型；D1 从 QKV/W1/W2 输出列分片入手。每种切分都明确输出所有权、scratch 所有权和 commit 依赖。先验证 2 SM，再扩到 4/8 SM，不能把单 SM 的面积最优当成多 SM 的架构最优。
2. 为值建立显式存储位置及生命周期：HBM、SH、RF。优先实现 D1 LN→QKV、W1→bias/GELU→W2 的驻留链，再扩展到 P1 row panel。寄存器分配器必须知道活跃值，不能让融合输入与 GEMM 累加器占用同一分区。
3. 搜索 producer/consumer 的 tile 对齐、DMA 双缓冲及独立计算的交错；只有冻结服务模型支持的重叠才计入预计收益。
4. 多 SM 分工确定后再配套搜索 RF 带宽、TC、SH、NoC/HBM 和 cache。避免为单 workgroup 的资源需求选择全局架构后就把拓扑固定。

外层状态必须记录结构组合和可继续扩展的后继。一次失败仅限制该布局/硬件/容量组合；例如 SH panel 失败不封禁 SH，K8 检查缓慢不封禁 N128。

## 逐层剪枝与评测漏斗

- **合法性证明**：每个 tile 的 RF/SH 容量、活跃分区数量、事件唯一性、输出恰好写一次、未来输入不可读、面积限制。不以历史小网格代替合法性条件。
- **小内核验证**：用独立受控数据检查索引、数值和读写依赖；测实际资源服务量。小内核通过不能替代完整 grade。
- **可评测性门槛**：对多 WG 的指令规模逐级增长，测 frozen race checker 时间/峰值内存；旧 cand-068 的资源中止只说明该规模和表达方式不适合当前验证预算。当前 K<16 的标量检查路径也归入成本策略。
- **性能下界与收益估计**：分别计算算力、RF、DMA/NoC、不可跨 step 的依赖链下界。不能把可重叠 busy 时间相加。只有证明即使理想调度也不可能改善才硬剪枝；估计不确定的结构进入小额探索队列。
- **完整 grade**：只有完整 P1+D1 通过才进入正确性档案并提升提交；保存 seed、耗时、峰值内存与全部原始报告。

前两级允许大量生成和静态筛选；完整 grade 按本机实际内存/吞吐限制并发，Gemini 的可用并发用于独立结构设计、源码核查和结果复核。

## 接下来三个结构任务

1. **多 WG 验证规模曲线 + 两 SM GEMM 列分片微型原型**：检查验证器的成本是否允许完整新布局；这决定可直接扩展的多 SM 粒度。
2. **D1 RF 驻留 FFN 原型**：引入活跃值分配和 W1/GELU/W2 的局部融合，删除中间 HBM ST/LD；目标是同时减少 RF 写回、DMA 和串行等待。
3. **多 SM 与驻留组合**：候选先各自验证，再组合；需要显式容量模型和 stage 依赖。以 5,000→10,000 的阶段目标衡量是否继续某条结构路线。

每条路线按“假设→可生成变换→资源预测→小内核证据→完整验证→保留/降权”记录。纯 tile 的连续低收益结果会降低该路线的预算，不会触发无限增加同类候选。
